\chapter{Data tables in SQL}

Every time you log in to a website, check your grades online, or buy
something with a card, a program somewhere asks a database a question,
probably in a language called SQL. It has been the standard way to talk
to data for fifty years, and it is still one of the most useful skills a
programmer can have.

\index{relational database}Most organizations keep their data as tables
inside a \newterm{relational database management system}, rather than in
CSV files or spreadsheets. Developers talk to those systems using a
language called SQL (``Structured Query Language'').
\index{SQL}

Some relational database managers are pricey products you may have
heard of before, such as Oracle or Microsoft SQL Server. Some are free, such as
PostgreSQL or MySQL. These are server software that client programs
talk to over a company's network.
\index{SQLite}

There is also a small, free database, called \texttt{sqlite}, that keeps
all its tables in a single file. It runs inside nearly every phone and web
browser on the planet. We can use SQL to create, edit, and browse those tables.
sqlite is free, fast, and very easy to install. We will use sqlite
instead of a networked database management system.

If you look in your digital resources, you will find a file called
\filename{bikes.db}. We created this file using sqlite, and now you
will use sqlite to access it.

In the terminal, get to the directory where \filename{bikes.db} lives. To open the sqlite tool on that file:

\begin{minted}{sql}
> sqlite3 bikes.db
\end{minted}

(If your system complains that there is no sqlite3 tool, you need to install sqlite. See this website: \url{https://sqlite.org/})

Please follow along: type each command shown here into the terminal
and see what happens.

We mostly run SQL commands in this tool, but there are a few non-SQL
 commands that all start with a period. To see the tables and their
 columns, you can run \texttt{.schema}:

\begin{minted}{sql}
sqlite> .schema
CREATE TABLE bike (bike_id int PRIMARY KEY, brand text, size int,
          purchase_price real, purchase_date date, status text);
\end{minted}

That is the SQL command that we used to create the \texttt{bike}
table. You can see all the columns and their types.

You want to see all the rows of data in that table?

\begin{minted}{sql}
sqlite> select * from bike;
4997391|GT|57|269.61|2009-05-03|rented
5429447|Cannondale|50|215.91|2002-02-17|broken
5019171|Trek|58|251.17|1985-07-11|rented
3000288|Cannondale|57|211.08|1993-01-05|broken
880965|GT|52|281.75|1995-08-02|available
...
\end{minted}

You will see 1000 rows of data!

SQL keywords and table names are not case-sensitive, so you can also
write it like this:
\begin{minted}{sql}
sqlite> SELECT * FROM BIKE;  
\end{minted}

Often, you will see SQL with just the SQL keywords in all caps:
\begin{minted}{sql}
sqlite> SELECT * FROM bike;  
\end{minted}
(The values inside quotes \emph{are} case-sensitive: \texttt{'GT'} and
\texttt{'gt'} are different brands to SQL.) The semicolon marks the end of
a command; it tells sqlite that you are done typing and it should run.

SQL lets you choose which columns you would like to see. The asterisk used above signifies all columns, and the \verb|bike_id, brand| only gets the bike's id and brand from the table:
\begin{minted}{sql}
sqlite> SELECT bike_id, brand FROM bike;
4997391|GT
5429447|Cannondale
5019171|Trek
3000288|Cannondale
...
\end{minted}

Using \index{WHERE}WHERE, SQL lets you use conditions to decide which rows you would like to see, and can be combined with the common operators \verb|AND|, \verb|OR|, and \verb|NOT|:
\begin{minted}{sql}
sqlite> SELECT * FROM bike WHERE purchase_date > '2009-01-01' AND brand = 'GT';
4997391|GT|57|269.61|2009-05-03|rented
326774|GT|56|165.0|2009-06-27|available
264933|GT|52|302.43|2009-07-09|available
5931243|GT|55|173.56|2009-11-26|rented
4819848|GT|51|221.71|2009-12-11|rented
9347713|GT|52|232.32|2009-06-13|available
3019205|GT|58|262.94|2009-08-22|available  
\end{minted}

Using \index{DISTINCT}DISTINCT, SQL lets you get just one copy of each value:
\begin{minted}{sql}
sqlite> SELECT DISTINCT status FROM bike;
rented
broken
available

Busted
Flat tire
good
out
Rented
\end{minted}

Look at that list. The blank line is a bike with no status at all
(SQL calls a missing value \texttt{NULL}). And someone has been typing
whatever they felt like: \texttt{Busted}, \texttt{Flat tire},
\texttt{Rented} with a capital R. Real data is messy.

You can fix it by editing rows. To change every \texttt{Busted} to
\texttt{broken}, use an \index{UPDATE}\verb|UPDATE| statement with a
\verb|SET|:

\begin{minted}{sql}
sqlite> UPDATE bike SET status='broken' WHERE status='Busted';
sqlite> SELECT DISTINCT status FROM bike;
rented
broken
available
Flat tire
good
out
Rented
\end{minted}

You can \index{INSERT}insert new rows:
\begin{minted}{sql}
sqlite> INSERT INTO bike (bike_id, brand, size, purchase_price, purchase_date, status)
  ...> VALUES (1, 'GT', 53, 123.45, '2020-11-13', 'available');
sqlite> SELECT * FROM bike WHERE bike_id = 1;
1|GT|53|123.45|2020-11-13|available
\end{minted}
The \texttt{bike\_id} must be \emph{unique}: it is the primary key, and
sqlite will refuse a second bike with the same ID.

You can \index{DELETE}delete rows:
\begin{minted}{sql}
sqlite> DELETE FROM bike WHERE bike_id = 1;
sqlite> SELECT * FROM bike WHERE bike_id = 1;
\end{minted}

Be careful: \verb|UPDATE| and \verb|DELETE| without a \verb|WHERE|
clause change or delete \emph{every} row in the table, and there is no
undo.

To get out of sqlite, type \texttt{.exit}.

\begin{Exercise}[title={Clean up the statuses}, label=sql_clean]
Write \verb|UPDATE| statements that change \texttt{Flat tire} to
\texttt{broken} and \texttt{Rented} to \texttt{rented}. Then run
\verb|SELECT DISTINCT status FROM bike;| to check your work. Which strange
values are left?
\end{Exercise}
\begin{Answer}[ref=sql_clean]
\begin{minted}{sql}
UPDATE bike SET status='broken' WHERE status='Flat tire';
UPDATE bike SET status='rented' WHERE status='Rented';
\end{minted}
After these, the distinct values are \texttt{rented}, \texttt{broken},
\texttt{available}, \texttt{NULL} (shown as a blank line), \texttt{good},
and \texttt{out}. Nobody knows what \texttt{good} or \texttt{out} were
supposed to mean, so you would have to ask someone at the shop before
fixing those.
\end{Answer}

\begin{Exercise}[title={SQL Query}, label=sql_where]
 Execute an SQL query that returns the \texttt{bike\_id} (no other
 columns) of every Trek bike that cost more than \$330.
\end{Exercise}
\begin{Answer}[ref=sql_where]
\begin{minted}{sql}
SELECT bike_id FROM bike WHERE purchase_price > 330 AND brand='Trek'
\end{minted}
\end{Answer}

\section{Using SQL from Python}\index{sqlite3 (Python library)}

The people behind sqlite created a library for Python that lets you
execute SQL and fetch the results from inside a python program.

Let us create a simple program that fetches and displays the bike ID
and purchase date of every Trek bike that cost more than \$330.

Create a file called \filename{report.py}:
\begin{minted}{python}
import sqlite3 as db

con = db.connect('bikes.db')
cur = con.cursor()

cur.execute("SELECT bike_id, purchase_date FROM bike WHERE purchase_price > 330 AND brand='Trek'")
rows = cur.fetchall()

for row in rows:
  print(f"Bike {row[0]}, purchased {row[1]}")

con.close()
\end{minted}

When you execute it, you should see:
\begin{minted}{sql}
> python3 report.py
Bike 4128046, purchased 2007-08-06
Bike 7117808, purchased 1995-03-12
Bike 7176903, purchased 1986-07-03
Bike 827899, purchased 2009-03-14
Bike 363983, purchased 1970-08-16
\end{minted}
