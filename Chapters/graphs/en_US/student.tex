\chapter{Introduction to Graphs}

\section{Introduction}

How does a map app find the fastest route across town? How does a social
network suggest people you might know? Both problems are about
\emph{connections}, and the math of connections is called graph theory.

In this chapter, a \newterm{graph} is not a plot on axes. It is a
collection of \newterm{nodes}\index{node} (also called vertices) joined by
\newterm{edges}\index{edge}. For example, on some social networks, each
user can follow any number of other users. We
can think of each user as a node, and the edge points from the user who
follows to the user they follow:

Following is a \newterm{directed} relationship: Fred232 follows SSontag, but SSontag does not
follow Fred232. So we would say that this is a \newterm{directed graph}
with four nodes and three edges.\index{graph!directed}

There are also undirected graphs. Imagine a graph of the big data lines
between cities. Data flows both ways on every line, like traffic on a
two-way road:\index{graph!undirected}

The arrows are gone; if data can flow from Miami to Raleigh, then
data can flow from Raleigh to Miami. A route that follows edges from one
node to another is called a \newterm{path}. The number of edges touching
a node is its \newterm{degree}. Atlanta and Charlotte each touch 3 edges, so each has a
degree\index{degree} of 3.


There is a whole branch of mathematics called \newterm{Graph Theory}
that studies the properties of graphs. Here are two questions that mathematicians
might ask about this graph:
\begin{itemize}
  \item What is the smallest number of edges that we would need to follow to get from Miami to Raleigh?
  \item Does the graph have any paths where you could end up where you
        started?
\end{itemize}

That second question asks if there is a \newterm{cycle}\index{cycle} in the graph. This graph has one
cycle: $\text{Atlanta} \rightarrow \text{Asheville} \rightarrow \text{Charlotte}
  \rightarrow \text{Atlanta}$.

Some graphs are \newterm{connected}: You can get from one node to any
other node by following edges. Is this graph connected?\index{graph!connected}

This graph is \textit{not} connected! You cannot follow edges from San
Diego to Seattle. It falls into two \index{connected
component}\newterm{connected components}: groups of nodes that are
connected to each other but not to anything else.
\begin{itemize}
  \item San Diego, Los Angeles, San Francisco
  \item Portland, Seattle, Spokane
\end{itemize}

To say it precisely: a graph is connected if there is a path between
every pair of its nodes. A \index{subgraph}\newterm{subgraph} is any part
of a graph: some of its nodes and some of the edges between them. Every
connected component is a subgraph, but most subgraphs are not connected
components.

In graph data, the nodes and edges often have attributes. For
example, a node representing a city might have a name and a
population. An edge representing a data line might have a bandwidth
(bits per second) and a latency (how long a bit takes to travel from one
end to the other).

\begin{Exercise}[title={Word Graphs}, label={ex:word_graph}]

  Consider the concept of a graph as a set of nodes and edges. How would you create a graph where the nodes are words and the edges represent a one letter difference between two words?

  For example, the word \texttt{cat} would be connected to \texttt{cot}, \texttt{cart}, and \texttt{cut}, but not to \texttt{dog}.

  Define explicitly what the nodes would be in this graph, and what the edges would be. Draw a simple example of this graph with at least 5 nodes and 5 edges.

\end{Exercise}

\begin{Answer}[ref={ex:word_graph}]

The nodes in this graph are unique words. The edges represent a valid one letter operations that can transform one word into another word. These operations include adding a letter, removing a letter, or changing a letter into another. For example, the word \texttt{cat} would be connected to \texttt{cot} (change), \texttt{cart} (add), and \texttt{cut} (change), but not to \texttt{dog}. Notice that this graph has cycles: \texttt{cat} $\to$ \texttt{cot}
$\to$ \texttt{cut} $\to$ \texttt{cat}. Word games like ``change one letter
at a time to turn \texttt{cold} into \texttt{warm}'' are really
path-finding puzzles on this graph.

\section{Finding Good Paths}

For many problems, we want the best path from one node to another. If all
the edges are alike, the best path is usually the one with the fewest
edges.

\textbf{Worked example.} A graph has edges $A$--$B$ costing 3, $B$--$C$
costing 4, and $A$--$C$ costing 9. What is the cheapest way from $A$ to
$C$?

\textbf{Solution.} The direct edge costs 9, but the path
$A \to B \to C$ costs $3 + 4 = 7$. The path with the fewest edges is not
always the cheapest.

Sometimes the edges have a cost attribute. For example, you might
want to find the cheapest way to ship a container from New York City
to Long Beach, California. In this case the nodes are train depots. Each
train line between the depots has a cost. What is the cheapest path?

Edges with costs are called \newterm{weighted edges}, and they form a
\index{weighted graph}\newterm{weighted graph}.

(In a \emph{directed} graph, a node's degree splits into two numbers: its
\newterm{in-degree}, the number of edges pointing into it, and its
\newterm{out-degree}, the number pointing out. In the ``following'' graph,
a user's in-degree is their number of followers.)

\begin{Exercise}[title={Ship it}, label=graph_ship]
Using figure \ref{fig:weighted}, find the cheapest way to ship a container
from New York City to Long Beach. What does it cost?
\end{Exercise}
\begin{Answer}[ref=graph_ship]
NYC $\to$ Cleveland $\to$ Denver $\to$ Los Angeles $\to$ Long Beach costs
$8 + 9 + 23 + 12 = \$52$. The next best route, through Louisville and
Denver, costs $28 + 14 + 23 + 12 = \$77$, and any route through Phoenix
costs more still.
\end{Answer}

The graphs that you see here are really small, so finding efficient
paths is not difficult --- you could just try all of them! However, in
many computer programs, we are working with \emph{millions} of nodes and
edges. Efficient graph algorithms are \textit{really} important.

\section{Graphs in Python}
There are many ways to represent graph data. There are database systems that are specifically designed to hold
and analyze graph data. Not surprisingly, these are called \newterm{Graph Databases}.

You may also hear about \newterm{adjacency lists}, which store, for each node, the list of nodes it is connected to.\index{adjacency list} Each direct connection from one node to another is called a \newterm{neighbor}. Simply, adjacency lists store lists of neighbors.

As an adjacency list, this would look like:
\begin{itemize}
  \item A: [B, C]
  \item B: [A, D]
  \item C: [A]
  \item D: [B]
\end{itemize}

\begin{Exercise}[title={Weighted Adjacency Lists}, label={ex:dir_adj}]

  \vspace{2cm}

  \begin{center}
    \vbox to 2cm{\vfil
        Consider the concept of adjacency lists discussed above. How would the storage method change if the edges were to have weights?
        \vfil}
  \end{center}

\end{Exercise}

\begin{Answer}[ref={ex:dir_adj}]

  In a weighted graph, each node stores its neighbors along with the weight
of each edge. A tuple works well. For example, if the edge A--B costs 4,
A--C costs 3, and B--D costs 8:
  \begin{itemize}
    \item A: [(B, 4), (C, 3)]
    \item B: [(A, 4), (D, 8)]
    \item C: [(A, 3)]
    \item D: [(B, 8)]
  \end{itemize}

\end{Answer}

For simplicity, you are going to write Python classes that will let
you represent an undirected graph with weighted edges, like the
shipping problem above.

(Naturally, things would look a little different if the graph were
directed or the edges were unweighted, but this is a good starting
place.)

Create a file called \filename{graph.py}. This will hold the code for
your \pytype{Node} and \pytype{WeightedEdge} classes. We will also
create a \pytype{Graph} class that will just hold onto the list of
its nodes.

\begin{itemize}
  \item A \pytype{Node} will have a label string and a list of edges that touch it.
  \item A \pytype{WeightedEdge} will have a cost and two nodes: \pyvar{node\_a} and \pyvar{node\_b}.
  \item A \pytype{Graph} will have a list of nodes.
\end{itemize}

Here is what the object diagram would look like if you had only three cities:

\includegraphics[width=0.8\textwidth]{objdiagram.png}

Put this code into \filename{graph.py}

\begin{minted}{python}
class Node:
  def __init__(self, label):
    self.label = label
    self.edges = []

  def __repr__(self):
    return f"(node:{self.label}, edges:{len(self.edges)})"

class WeightedEdge:
  def __init__(self, cost, node_a, node_b):
    self.cost = cost
    self.node_a = node_a
    node_a.edges.append(self)
    self.node_b = node_b
    node_b.edges.append(self)

  def other_end(self, node_from):
    if self.node_a == node_from:
      return self.node_b
    if self.node_b == node_from:
      return self.node_a
    raise ValueError("node is not an endpoint of this edge")

class Graph:
  def __init__(self):
    self.nodes = []

  def add_node(self, new_node):
    self.nodes.append(new_node)

  def __repr__(self):
    return f"(Graph:{self.nodes})"
\end{minted}
The \pyfunction{other\_end} method answers ``if I am at this node, where
does this edge take me?'' You will need it to walk through the graph.
Now, let us create some instances of \pytype{Node} and
\pytype{WeightedEdge} and wire them together. Create another file in
the same directory called \filename{cities.py}. Put in this code:

\begin{minted}{python}
import graph

# Create an empty graph
network = graph.Graph()

# Create city nodes and add to graph
long_beach = graph.Node("Long Beach")
network.add_node(long_beach)
los_angeles = graph.Node("Los Angeles")
network.add_node(los_angeles)
denver = graph.Node("Denver")
network.add_node(denver)
phoenix = graph.Node("Phoenix")
network.add_node(phoenix)
louisville = graph.Node("Louisville")
network.add_node(louisville)
cleveland = graph.Node("Cleveland")
network.add_node(cleveland)
boston = graph.Node("Boston")
network.add_node(boston)
nyc = graph.Node("New York City")
network.add_node(nyc)

# Create edges
graph.WeightedEdge(12, long_beach, los_angeles)
graph.WeightedEdge(23.0, los_angeles, denver)
graph.WeightedEdge(19, los_angeles, phoenix)
graph.WeightedEdge(52, phoenix, louisville)
graph.WeightedEdge(14, denver, louisville)
graph.WeightedEdge(80, phoenix, cleveland)
graph.WeightedEdge(9, denver, cleveland)
graph.WeightedEdge(8, cleveland, nyc)
graph.WeightedEdge(28, louisville, nyc)
graph.WeightedEdge(7, nyc, boston)
graph.WeightedEdge(13, cleveland, boston)

print(network)
\end{minted}

\begin{Exercise}[title={Cheapest Route}, label=graph1]
Edges $A$--$B$ cost $2$, $B$--$D$ cost $5$, $A$--$C$ cost $4$, and $C$--$D$ cost $3$. What is the cheapest route from $A$ to $D$, and what does it cost?
\end{Exercise}
\begin{Answer}[ref=graph1]
Route $A \to C \to D$ costs $4 + 3 = 7$. Route $A \to B \to D$ costs $2 + 5 = 7$. Both routes tie at $7$.
\end{Answer}
