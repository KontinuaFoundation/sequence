\chapter{Data Tables and pandas}
Your school keeps a table of every student: name, grade, schedule. A
streaming service keeps a table of every song you have played. Most of the
data you will ever work with arrives as a table: a spreadsheet, a database,
or a plain text file. In this chapter, you will learn pandas, the Python
library that data scientists use to read, clean, and question tables.

Each column holds one attribute (like height or acreage), and each row
holds one thing (like a person or a farm). Here is a table about houses:

\begin{tabular}{c | c | c | c}
  \texttt{property\_id} & \texttt{bedrooms} & \texttt{square\_meters} & \texttt{estimated\_value} \\
  \hline
  7927 &  3 & 121.4 & \$ 294,393 \\
  9329 &  2 & 82.9 & \$ 207,420 \\
\end{tabular}

Usually one column is guaranteed to be different in every row. We call it
the \newterm{primary key}\index{primary key}, and it works like a student
ID number.  In this table, \texttt{property\_id} is
the primary key; every property has one, and no two properties have
the same \texttt{property\_id}.

\section{Data types}

Each column has a type, and the types match Python's types nicely.

Here are some common datatypes:
\index{datatypes}
\begin{tabular}{c | c | c }
  Type & Python type & Example \\
  \hline
  Integer & int & \texttt{910393} \\
  Float & float & \texttt{-23.19} \\
  String & str & \texttt{'Fred'} \\
  Boolean & bool & \texttt{False} \\
  Date & datetime.date & \texttt{2019-12-04} \\
  Timestamps & datetime.datetime & \texttt{2022-06-10T14:05:22Z} \\
\end{tabular}

Sometimes it is OK to have values missing.  For example, if you had a
table of data about employees, maybe one of the columns would be
\texttt{retirement} --- a date that tells you when the person retired.  People who
had not yet retired would have no value in this column.  We would say
that they have \newterm{null} for \texttt{retirement}.\index{null}

Sometimes there are constraints on what values can appear in the
column.  For example, if the column were \texttt{height}, it would make no
sense to have a negative value.

Sometimes a column can only be one of a few values. For example, if
you ran a bike rental shop, each bicycle's status would be ``available'',
``rented'', or ``broken''.  Any other values in that column would not
be allowed.  We often call these columns \newterm{categorical}\index{categorical variable}.

\section{pandas}



\index{pandas}
Python programmers work with tables so often that they built a library
just for them: pandas. You could loop through a table one row at a time,
but for a table with millions of rows, that is slow. pandas lets you say
things like ``delete every row that has no value for height'' in one line,
and it runs fast.

In pandas, there are two datatypes that you use a lot:
\begin{itemize}
\item a \index{Series}\texttt{Series} is a single column of data.
\item a \index{DataFrame}\texttt{DataFrame} is a table of data: it has a \texttt{Series} for each column.
\end{itemize}

\textbf{Worked example.} Build a small DataFrame of test scores and find
the average.
\begin{minted}{python}
import pandas as pd

scores = pd.DataFrame({"name": ["Ana", "Ben", "Cy"], "score": [88, 92, 75]})
print(scores["score"].mean())
\end{minted}
The output is \mintinline{text}{85.0}. Square brackets pick out the
\texttt{score} column (a Series), and \mintinline{python}{mean()} averages
it.

\begin{Exercise}[title={Highest Score}, label=pd1]
Using the \texttt{scores} DataFrame above, write code that prints the highest score.
\end{Exercise}
\begin{Answer}[ref=pd1]
\begin{minted}{python}
print(scores["score"].max())
\end{minted}
The output is \mintinline{text}{92}.
\end{Answer}

\section{Reading a CSV with pandas}

Let us make a program that reads \filename{bikes.csv} into a pandas
dataframe.  Create a file called \filename{report.py} in the same
folder as \filename{bikes.csv}.

pandas treats one column as the primary key and calls it the
\index{pandas!index}\newterm{index}. When we read the file, we will tell
pandas to use \texttt{bike\_id} as the index.

If you ask a dataframe for its shape, it returns a tuple containing
the number of rows and the number of columns. To confirm that we have
actually read the data in, let us print those numbers.  Add these lines
to \filename{report.py}:

\begin{minted}{python}
import pandas as pd

# Read the CSV and create a dataframe
df = pd.read_csv('bikes.csv', index_col="bike_id")

# Show the shape of the dataframe
(row_count, col_count) = df.shape
print(f"*** Basics ***")
print(f"Bikes: {row_count:,}")
print(f"Columns: {col_count}")
\end{minted}

Run it. You should see:
\begin{minted}{python}
*** Basics ***
Bikes: 998
Columns: 5
\end{minted}

The file has six columns, but the shape says five. The index does not
count as a column.

\section{Looking at a Series}

Let us get the lowest, the highest, and the mean purchase price of the
bikes.  The purchase price is a series, and you can ask the dataframe
for it. Add these lines to the end of your program:

\begin{minted}{python}
# Purchase price stats
print("\n*** Purchase Price ***")
series = df["purchase_price"]
print(f"Lowest:{series.min()}")
print(f"Highest:{series.max()}")
print(f"Mean:{series.mean():.2f}")
\end{minted}

Now when you run it, you will see a few additional lines:
\begin{minted}{python}

Lowest:107.37
Highest:377.7
Mean:249.01
\end{minted}

What are all the brands of the bikes? Add a few more lines to your

# Brand stats
print("\n*** Brands ***")
series = df["brand"]
series_counts = series.value_counts()
print(f"{series_counts}")

\pyfunction{value\_counts} returns a Series.  To format this better, we

\section{Rows and the index}

In a list, you ask for an item by its position. pandas does that with
\pyfunction{iloc} (``integer location''). Add
this to the end of your program:

\begin{minted}{python}
# First bike
print("\n*** First Bike ***")
row = df.iloc[0]
print(f"{row}")
\end{minted}

When you run it, you will see the attributes of the first row of data:

\begin{minted}{python}
*** First Bike ***
brand                     GT
size                      57
purchase_price        277.99
purchase_date     1986-09-07
status             available
Name: 5636248, dtype: object
\end{minted}

The row comes back as another Series.

The last line says that this row's name (its index value) is 5636248.
Usually we find rows by their index, not their position, using
\pyfunction{loc}. For example, there is a bike with \texttt{bike\_id}
2969341. Let us ask for its brand:

\begin{minted}{python}
print("\n*** Some Bike ***")
brand = df.loc[2969341]['brand']
print(f"brand = {brand}")
\end{minted}

Now, you will see the information about that bike:

\begin{minted}{python}
*** Some Bike ***
brand = Cannondale
\end{minted}

pandas has a few different ways of getting to that value.  All of these get you the same thing:
\begin{minted}{python}
brand = df.loc[2969341]['brand'] # Get row, then get value
brand = df['brand'][2969341]     # Get column, then get value
brand = df.loc[2969341, 'brand'] # One call with both row and value
\end{minted}

\section{Changing data}

Real data is messy. Every bike should have a status, and it should be one
of ``available'', ``rented'', or ``broken''. Let us count each value that
actually appears:

\begin{minted}{python}
print("\n*** Status ***")
series = df["status"]
missing = series.isnull()
print(f"{missing.sum()} bikes have no status.")
series_counts = series.value_counts()
for value in series_counts.index:
    print(f"{series_counts.loc[value]} bikes are \"{value}\"")
\end{minted}

This will show you:

\begin{minted}{python}
*** Status ***
7 bikes have no status.
389 bikes are "rented"
304 bikes are "broken"
296 bikes are "available"
1 bikes are "Flat tire"
1 bikes are "Available"
\end{minted}

Somebody typed ``Available'' with a capital A, and somebody else typed
``Flat tire.'' Right after you read the CSV, fix the first problem:

\begin{minted}{python}
mask = df['status'] == 'Available'
print(f"{mask}")
df.loc[mask, 'status'] = 'available'
\end{minted}

When you run this, you will see that the mask is a series with
\texttt{bike\_id} as the index and \texttt{False} or \texttt{True} as the value,
depending on whether the row's status was equal to ``Available''.

When you use \pyfunction{loc} with this sort of mask, you are saying
``Give me all the rows for which the mask is True.''  So, the
assignment only happens in the one problematic row.

You do not need the \texttt{mask} variable. Here is the same fix in one
line, plus one that turns \texttt{Flat tire} into \texttt{broken}:

\begin{minted}{python}
df.loc[df['status'] == 'Available', 'status'] = 'available'
df.loc[df['status'] == 'Flat tire', 'status'] = 'broken'
\end{minted}

Now those problems are gone:
\begin{minted}{python}
7 bikes have no status.
389 bikes are "rented"
305 bikes are "broken"
297 bikes are "available"
\end{minted}

What about the 7 bikes with no status? If we were sure they were
available, we could fill in the blanks:

\begin{minted}{python}
missing_mask = df['status'].isnull()
df.loc[missing_mask, 'status'] = 'available'
\end{minted}

Or we could print their IDs so someone can go find them:

\begin{minted}{python}
missing_mask = df['status'].isnull()
missing_ids = list(df[missing_mask].index)
print(f"These bikes have no status:{missing_ids}")
\end{minted}

Instead, let us just keep the rows where the status is not null. The
\texttt{\textasciitilde} flips every True to False and every False to True:
\begin{minted}{python}
missing_mask = df['status'].isnull()
df = df[~missing_mask]
\end{minted}

At the end of your program, write out the improved CSV:

\begin{minted}{python}
df.to_csv('bikes2.csv')
\end{minted}

Run the program and open \filename{bikes2.csv} in a text editor.

\section{Derived columns}

Now add a new column, the age of each bike in days, so that
\filename{bikes2.csv} starts like this:
\begin{minted}{python}
bike_id,brand,size,purchase_price,purchase_date,status,age_in_days
5636248,GT,57,277.99,1986-09-07,available,13061
4156134,Giant,56,201.52,2005-01-09,rented,6362
7971254,Cannondale,54,292.25,1978-02-28,available,16174
\end{minted}

First problem: \texttt{purchase\_date} looks like a date, but pandas read
it as a string. Convert it by applying a function to every item in the
Series. (Add \mintinline{python}{import datetime} at the top of your
program.)
\begin{minted}{python}
df['purchase_date'] = df['purchase_date'].apply(lambda s: datetime.date.fromisoformat(s))
\end{minted}

(With pandas, there is often more than one way to do things.  pandas
has a \pyfunction{to\_datetime} function that converts every entry in
a sequence to a \pytype{datetime} object. Here is another way to
convert the string column into a date column:
\begin{minted}{python}
df['purchase_date'] = pd.to_datetime(df['purchase_date']).dt.date
\end{minted}
You can look up \pyfunction{dt} and \pyfunction{date} if you are curious.)

Now, we can use the same trick to create a new column with the age in days:
\begin{minted}{python}
today = datetime.date.today()
df['age_in_days'] = df['purchase_date'].apply(lambda d: (today - d).days)
\end{minted}

Run it, and \filename{bikes2.csv} will have an \texttt{age\_in\_days}
column. (Your numbers will be bigger than ours; the bikes keep getting
older.)
